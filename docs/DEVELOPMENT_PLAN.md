# OpsPilot 开发与业务更新计划

> 更新：2026-09-16。以个人开发的电商售后数字化工具为基础，按业务需求逐步完善。
> 本文中的计划不代表已实现能力；当前状态以代码和[验证记录](./TESTING_BASELINE.md)为准。

## 当前基础

已实现内部坐席退款工单、HTTP 流程接入、政策证据检索、带版本审批、幂等执行、未知结果对账、
PG 持久化、顺序重启恢复与审计关联。合成样本用于验证规则、权限和状态，真实支付及企业身份尚未接通。
单 Agent 为默认路径，多角色编排保留为可选对照实验。

已完成的可靠性整改包括 checkpoint 键隔离、响应与日志脱敏、线程审计关联、异常收尾恢复、
独立进程租约验证以及审计事件持久标识。历史问题继续保留在[缺陷台账](./DEFECTS_LOG.md)，不重复安排为待开发功能。

## 按优先级推进

| 优先级 | 工作内容 | 完成条件 | 状态 |
| --- | --- | --- | --- |
| 1 | 持续维护退款闭环与确定性业务边界 | 正常路径和失败路径均有断言；金额、权限、审批、幂等、状态及审计不变量通过 | 已有基础，持续维护 |
| 2 | 扩充故障注入与恢复验证 | 覆盖依赖超时、收尾失败、租约竞争及重启；每项记录业务最终状态与退款次数 | 部分覆盖，继续完善 |
| 3 | 完善故障定位与观测 | 建立线程、工单、操作、审计之间的关联；汇总等待、转人工及错误原因，日志保持脱敏 | 审计关联已实现，观测汇总待设计 |
| 4 | 工作台可用性与浏览器回归 | 正常、澄清、拒绝、对账、越权和循环停止均可验证；错误提示对应可执行的下一步 | 当前有接口级记录，浏览器自动化待补 |
| 5 | 真实模型影子验证 | 获得授权及安全配置后，以同一数据集记录质量、降级、延迟及实际成本；不触发业务写入 | 入口已实现，真实调用未实测 |
| 6 | 按测量结果优化性能与模型 | 先给出负载、瓶颈和对照指标，再决定检索、缓存或训练方案 | 尚未压测或训练 |

CI 配置已包含隔离 PostgreSQL 建库、迁移与分层回归入口；远程运行是否通过须以对应提交的实际运行记录为准。
独立故障任务、观测平台等不能因已有 CI 文件而视为已完成。

## 企业业务拓展方向

以下是待评估方向，不构成当前业务承诺或自动实施授权：

| 方向 | 需要补充的业务设计 | 纳入条件 |
| --- | --- | --- |
| 退货与换货 | 逆向物流、收货验收、商品状态、退款关联及异常处理 | 明确状态机与异常样本，完成方案确认 |
| 补发 | 可用库存、出库请求、运费承担、重复请求与撤销规则 | 建立库存与执行事实源，明确审批职责 |
| 物流只读接入 | 数据授权、字段映射、时效、不可用响应与引用来源 | 使用独立测试环境，不伪造物流事实 |
| 客户自助服务 | 客户认证、订单归属、可见字段、限流和人工转接 | 独立设计客户与坐席权限边界 |
| 企业系统接入 | 身份管理、数据治理、凭证管理、对账协议及回滚方案 | 获得明确授权与独立安全方案 |

## 每次业务更新的工作顺序

1. 阅读工程规则、项目首页及相关设计；检查已有工作区改动。
2. 明确问题属于工作流、领域服务、数据、评测、界面还是文档。
3. 先定义状态、权限、错误、幂等与审计语义，再实施最小变更。
4. 运行针对性验证；影响业务闭环时追加黄金集与相关 PG 回归。
5. 保留原始结果和失败信息，同步状态、基线、缺陷台账与使用说明。
6. 新副作用、业务范围扩展或事实源变更，先完成方案确认再实施。

可复用的任务说明见[维护任务指引](./MAINTENANCE_TASK_GUIDE.md)。
