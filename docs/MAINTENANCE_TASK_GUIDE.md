# OpsPilot 项目维护任务指引

> 用途：支持个人开发中的问题修复、业务更新尝试、验证复跑与文档维护。
> 更新：2026-09-16。按当前仓库定位代码，不沿用历史行号或测试数量。

## 可复用任务说明

你负责 OpsPilot 电商售后数字化工具的维护。先阅读 `AGENTS.md`、`README.md`、
`docs/ARCHITECTURE.md`、`docs/STATUS_AND_RISKS.md`、`docs/TESTING_BASELINE.md` 与
`docs/DEVELOPMENT_PLAN.md`，再检查工作区和当前提交。保留已有文件、数据与无关改动。

围绕本次明确提出的业务问题工作，不预设新增模型、外部平台或存储组件。先记录问题触发条件、
当前行为与期望行为，定位属于工作流、领域服务、数据、评测、界面或文档的哪一层。

业务设计应明确以下事项：

- **状态**：从哪个状态允许进入哪个状态，失败与未知结果如何保留。
- **权限**：调用者角色、租户、资源归属，以及是否需要人工审批。
- **幂等与并发**：同键同载荷复用原结果，同键异载荷拒绝；未知结果只能原操作对账。
- **审计**：记录对象、操作、身份及关联标识，日志与返回值保持脱敏。
- **恢复**：从领域事实重读，不以模型输出、请求体或 checkpoint 代替审批与执行结果。

实施最小修复，按风险运行针对性测试。业务变更应覆盖正常路径和至少一个失败路径；
需要证明回归有效时，可使用隔离环境做有界的变异验证，结束后恢复源码。
文档措辞或链接更新执行静态核对即可，不必把未运行的业务测试写成通过。

涉及 PG 的破坏性测试，只允许显式 `OPSPILOT_TEST_DATABASE_URL` 指向本机
`opspilot_test_*` 隔离库。先建库并将迁移指向该库，不回退共享 `DATABASE_URL`。
数据库不可用时如实记录跳过，不能将内存结果当作 PG 验证。

本机运行前执行 `scripts/init_d_env.ps1`，使用 D 盘 `.venv`，临时文件和缓存留在项目目录。
不写入真实客户资料、支付资料或企业凭证；真实模型与外部系统接入须满足已有授权边界。
业务范围、新副作用或事实源发生变化时，先提供具体方案并获得确认。

## 交付要求

交付应说明修复了什么、影响哪条电商售后流程、正常和失败行为是什么，并提供：

1. 与实际代码一致的实现说明与限制。
2. 实际运行的命令、环境、日期、通过 / 失败 / 跳过结果。
3. 对金额、权限、状态、幂等、审批与审计的影响。
4. 未运行、未实现、未实测项目的明确标记。
5. 同步后的项目首页、状态、相关设计与缺陷记录。

评测报告保留模型、Prompt、数据集及运行模式标识；合成数据不代表真实运营效果。
不覆盖历史失败结果，不将不同提交的结果合并成一次运行。
Git 提交与上传按当前用户授权范围执行，不改写已有历史。
